Q: explain dependency injection in fastapi
A: Dependency Injection (DI) in FastAPI is a software design pattern where a component (like a route handler) declares what it needs to work (its dependencies), and the framework automatically supplies those components at runtime.
Instead of writing repetitive code to manually build database sessions, validate tokens, or parse query parameters inside every single endpoint, you write that logic once as a standalone function or class. You then tell FastAPI to "inject" the result directly into your route functions.
------------------------------
## How Dependency Injection Operates
FastAPI implements its DI system using the Depends function and standard Python type annotations (often utilizing Annotated).
When a client hits an endpoint, FastAPI looks at the path operation parameters. If it sees a parameter declared with Depends(dependency_callable), it halts execution of the route handler, runs the dependency first, and passes whatever that dependency returns as the argument into your route handler.

from typing import Annotatedfrom fastapi import FastAPI, Depends
app = FastAPI()
# 1. Define the dependency logicdef common_pagination_params(skip: int = 0, limit: int = 100):
    return {"skip": skip, "limit": limit}
# 2. Inject it into a route
@app.get("/items/")async def read_items(commons: Annotated[dict, Depends(common_pagination_params)]):
    return {"message": "Fetching items", "params": commons}

## Advanced Operational Features:

* 
* Automatic Sub-dependencies: If your dependency function requires another dependency to work, FastAPI will automatically figure out the execution order, resolve the nested dependency recursively, and inject it. [1, 8] 
* Resource Cleanup with yield: Dependencies can manage setup and teardown lifecycle behaviors using standard Python generators. If you use yield instead of return, FastAPI will execute everything before the yield statement, pass the yielded value to the endpoint, and run the code after yield (like closing a database connection) after the response is sent back. [4, 9, 10] 
* Class-based Dependencies: Beyond functions, you can use classes as dependencies. When configured this way, FastAPI treats the class constructor as the executable and injects an instance of the class. [2, 7]

## Practical Applications## 1. Database Session Management
Instead of opening and closing database sessions manually per endpoint, a dependency handles the entire lifecycle safely. [2] 

from sqlalchemy.orm import Session
def get_db():
    db = SessionLocal()
    try:
        yield db  # Provide the session to the endpoint
    finally:
        db.close() # Executed automatically after the request finishes

@app.get("/users/{user_id}")def get_user(user_id: int, db: Annotated[Session, Depends(get_db)]):
    return db.query(User).filter(User.id == user_id).first()

## 2. Authentication & Security
You can isolate route authorization checks into a single block of middleware logic. If authorization fails, the dependency raises an exception, aborting the execution of the route handler entirely. [5, 10] 

from fastapi import Header, HTTPException
def verify_api_key(x_api_key: Annotated[str, Header()]):
    if x_api_key != "secret-token-value":
        raise HTTPException(status_code=401, detail="Invalid API Key")
    return x_api_key

@app.get("/secure-data/")def get_data(api_key: Annotated[str, Depends(verify_api_key)]):
    return {"secure_info": "This endpoint is protected."}

## 3. Streamlined Unit Testing
Because your route logic does not hardcode things like database links or third-party service connections, you can dynamically swap dependencies out during automated testing using the framework's [dependency overrides dictionary](https://fastapi.tiangolo.com/advanced/testing-dependencies/) (app.dependency_overrides). This makes it simple to inject mock databases or mock users without altering a single line of production code. [1, 4]
