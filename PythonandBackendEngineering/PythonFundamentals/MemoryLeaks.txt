Q: Explain memory leaks
A: A memory leak in Python happens when unused objects stay in computer memory because the program accidentally keeps a reference to them, preventing Python's built-in garbage collector from clearing them.
Even though Python has automated memory management, memory can still leak if your code holds active pathways to objects that you no longer need. Over time, these hidden references consume more and more RAM until your application slows down or crashes with an out-of-memory error.
------------------------------
## How Python Manages Memory
Python relies on two main mechanisms to clean up memory:

* Reference Counting: Python keeps track of how many variables or structures point to an object. When that count drops to zero, Python deletes the object immediately.
* Garbage Collector (GC): Python runs a separate cyclic garbage collector to find and clean up complex loops where objects reference each other, even if their reference count is above zero.

A memory leak occurs when these mechanisms fail to see an object as "unused" because a live part of your program still points to it.
------------------------------
## Common Causes of Memory Leaks in Python## 1. Growing Global Caches and Lists

* The Issue: Storing data in global variables, lists, or dictionaries that never get cleared or limited in size.
* Why it leaks: A global dictionary that caches function results or user sessions will live for the entire lifetime of the process, holding onto objects forever.

## 2. Circular References with Destructors (__del__)

* The Issue: Two objects reference each other (Object A points to Object B, and Object B points to Object A).
* Why it leaks: While Python's garbage collector usually breaks cycles, objects that define a custom __del__ destructor method can confuse the collector in older Python versions, leaving them stranded in memory.

## 3. Forgotten Event Listeners and Callbacks

* The Issue: Registering an object's method as a callback or event listener with a long-lived manager or GUI framework.
* Why it leaks: If you forget to unregister the listener, the manager holds a reference to your object, preventing it from ever being garbage-collected.

## 4. Closures and Scope Retention

* The Issue: Defining inner functions or closures that capture large local variables in their enclosing scope.
* Why it leaks: If the outer function finishes but the closure remains active somewhere in the program, those large captured variables stay trapped in memory.

Q: Explain garbage collector in python, how it is different from other languages?
A: Python uses a dual hybrid approach to garbage collection that combines Reference Counting with a generational Cyclic Garbage Collector (GC).
While most popular managed languages rely on a single background engine that pauses your program to scan all memory, Python cleans up the vast majority of its objects instantly the millisecond they are no longer needed.
------------------------------
## The Two Layers of Python's Garbage Collection
Python uses two distinct layers to manage and clean up memory:
## Layer 1: Reference Counting (Primary)
Every object in Python contains a hidden field called a reference count. This number tracks how many variables, lists, dictionaries, or properties are currently pointing to that object.

* 
* Instant Cleanup: The exact moment a reference count drops to 0, Python immediately deallocates the object and frees its memory back to the interpreter.
* Pros: Deterministic, instantaneous, and incurs no pauses or delays in your code execution.
* 

## Layer 2: Generational Cyclic GC (Secondary)
Reference counting has a major blind spot: circular references. If Object A references Object B, and Object B references Object A, their reference counts will never drop to 0, even if the rest of your program completely forgets about them.
To solve this, Python runs a scheduled, generational garbage collector in the background:

* 
* The Strategy: It groups objects into three generations (Gen 0, Gen 1, and Gen 2). New objects start in Gen 0. If they survive a collection cycle, they are promoted to Gen 1, and eventually Gen 2.
* The Mechanism: The GC actively hunts for isolated "islands" of objects that are only referencing each other but are unreachable from the root execution pointer, breaking the loops and freeing the memory.
* 

------------------------------
## How Python Differs from Other Languages
Python's hybrid approach sets it apart from major runtime systems like Java, C#, or JavaScript.

| Feature / Behavior | Python (CPython) | Java (JVM) / C# (.NET) | JavaScript (V8 Engine) |
|---|---|---|---|
| Primary Mechanism | Reference Counting + Generational Cyclic GC | Tracing GC (Mark-and-Sweep, G1, etc.) | Tracing GC (Generational Mark-and-Sweep) |
| Destruction Timing | Immediate for non-cyclic objects; deferred for cycles. | Deferred. Objects stay in memory until a sweep triggers. | Deferred. Cleanups occur unpredictably based on heuristics. |
| "Stop-the-World" Pauses | Extremely short. Only triggers to scan structural cycles. | Variable. Can cause noticeable application freezes during full sweeps. | Minor. Uses incremental/concurrent marking to minimize freezes. |
| Memory Overhead | High. Every single object must store an integer tracking its references. | Low to Medium. No per-object reference counters are required. | Low. Relies on graph reachability maps instead of counters. |

## The Core Philosophies Compared## 1. Python vs. Java/C# (Immediate vs. Batch)
Java and C# completely skip reference counting. When an object dies in Java, it remains in memory as "garbage" until the JVM decides the heap is too full. It then performs a Tracing collection, which maps out every live object, sweeps away the dead ones, and compacts the memory. Python, by contrast, handles cleanup incrementally throughout execution, saving the tracing overhead only for circular traps.
## 2. Python vs. JavaScript (Predictable vs. Heuristic)
JavaScript engines (like V8) use advanced generational tracing that runs concurrently with your code to minimize pauses. However, you can never predict exactly when a piece of memory will be reclaimed in JavaScript. In Python, dropping a local variable name or exiting a function scope guarantees the immediate destruction of its standalone child objects.
