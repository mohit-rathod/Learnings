Q: Explain Type Hints
A: In Python, type hints allow you to explicitly state the expected data types for variables, function arguments, and return values. While Python remains dynamically typed at runtime, type hints are essential for high-throughput engineering—they enable IDE autocompletion, catch bugs before execution via static type checkers like mypy, and clarify code intent for team collaborations.
Here is a comprehensive breakdown of all major type hinting categories, grouped by their architectural purpose, followed by a complete end-to-end production example.
------------------------------
## 1. Primitive Type Hints
These are the foundational built-in types used for basic variables and parameters.

* str: Text data.
* int: Whole numbers.
* float: Floating-point decimal numbers.
* bool: True/False values.
* bytes: Raw byte sequences (e.g., tokenized strings or network payloads).

------------------------------
## 2. Collection Type Hints (Python 3.9+)
Used to specify the types of items inside collections. Modern Python allows you to use standard built-in structures directly for nesting.

* list[T]: A homogenous dynamic array where elements are of type T.
* set[T]: A collection of unique elements of type T.
* dict[K, V]: A map matching unique keys of type K to values of type V.
* tuple[T, ...]: A variable-length tuple where all elements are of type T.
* tuple[A, B, C]: A fixed-length tuple where the exact index positions matter (index 0 is A, index 1 is B, etc.).

------------------------------
## 3. Structural & Logical Operators
These handle real-world logic where a variable might accept multiple types or have a default empty state.

* Union (X | Y): Used when an argument or return value can be multiple types (e.g., int | float). Note: Replaces typing.Union in Python 3.10+.
* Optional (X | None): Specifically explicitly states that a value can either be of type X or safely contain None. Note: Replaces typing.Optional.
* Any: Bypasses the type checker entirely. Use sparingly, as it accepts any data type and shuts down structural safety validation.
* Literal[...]: Restricts a value to an exact set of specific, hardcoded primitives (e.g., Literal["GPT-4", "Llama-3"]).

------------------------------
## 4. Advanced & Functional Type Hints
For complex patterns like callbacks, stream processing, class structures, or structural subtyping.

* Callable[[Arg1, Arg2], ReturnType]: Hints at functions passed as arguments (callbacks) or returned from decorators.
* Iterator[T] / Generator[YieldT, SendT, ReturnT]: Used for streaming functions, loops, or lazy token generation arrays.
* Self: Available in Python 3.11+, it tells the compiler that a class method returns an instance of its own class (perfect for fluent APIs or factory patterns).
* Protocol: Structural subtyping (Static Duck Typing). Defines a blueprint of methods an object must have, rather than forcing strict class inheritance.

------------------------------
## Comprehensive Production Example: High-Throughput LLM Pipeline
The script below demonstrates when and how to use every single one of these type hints in a clean, production-grade architecture.

from typing import Any, Callable, Generator, Literal, Protocol, Selfimport time
# 1. STRUCTURAL SUBTYPING (Protocol)# Used when you care about *what an object does*, not its class hierarchy.class TokenizerProtocol(Protocol):
    def encode(self, text: str) -> list[int]: ...
    def decode(self, tokens: list[int]) -> str: ...

# A concrete class implementing the protocolclass SimpleTokenizer:
    def encode(self, text: str) -> list[int]:
        return [len(word) for word in text.split()]  # Mock tokenization ids

    def decode(self, tokens: list[int]) -> str:
        return " ".join(["a" * t for t in tokens])

# 2. DATA CONTAINER WITH 'SELF'class LLMConfig:
    def __init__(self, model_name: Literal["llama3", "gpt4"]) -> None:
        self.model: str = model_name
        self.temperature: float = 0.7

    # Use 'Self' for method chaining configurations
    def set_temperature(self, value: float) -> Self:
        self.temperature = value
        return self

# 3. CALLABLE & COMPLEX TYPE HINTS# Decorator capturing a function, timing it, and maintaining exact signature hintsdef time_pipeline(
    func: Callable[[str, LLMConfig, TokenizerProtocol], Generator[str, None, None]]
) -> Callable[[str, LLMConfig, TokenizerProtocol], Generator[str, None, None]]:
    def wrapper(
        prompt: str, config: LLMConfig, tokenizer: TokenizerProtocol
    ) -> Generator[str, None, None]:
        start: float = time.perf_counter()
        yield from func(prompt, config, tokenizer)
        print(f"\n[Metrics] Streaming pipeline took: {time.perf_counter() - start:.5f}s")
    return wrapper

# 4. DICTIONARIES, UNIONS, AND GENERATORS IN ACTION# A pipeline processing raw data, tracking performance metadata, and yielding dynamic updates
@time_pipelinedef process_prompt_stream(
    prompt: str, 
    config: LLMConfig, 
    tokenizer: TokenizerProtocol
) -> Generator[str, None, None]:
    """Processes an incoming string and yields generated token pieces dynamically."""
    
    # Primitive and collection hinting inside functions
    raw_bytes: bytes = prompt.encode("utf-8")
    token_ids: list[int] = tokenizer.encode(prompt)
    
    # Meta dict mapping string metadata keys to mixed scalar values using Union (|)
    metadata: dict[str, int | float | str] = {
        "model": config.model,
        "byte_size": len(raw_bytes),
        "token_count": len(token_ids)
    }
    print(f"[System Init] Configured metadata tracking: {metadata}")

    # Banned system tokens check using a Set hint
    banned_tokens: set[int] = {0, -1, 999}
    
    # Simulated stream generation
    for token in token_ids:
        if token in banned_tokens:
            continue
        time.sleep(0.1) # Simulate inference lag
        yield f"Token({token}) "

# 5. FIXED-LENGTH TUPLES AND OPTIONAL INPUT HANDLINGdef run_pipeline_job(
    payload: tuple[str, Literal["llama3", "gpt4"]], 
    custom_temp: float | None = None
) -> None:
    """Unpacks a structured job tuple and initiates inference."""
    # Unpacking fixed size positional tuple
    prompt, model_choice = payload
    
    config = LLMConfig(model_name=model_choice)
    if custom_temp is not None:
        config.set_temperature(custom_temp)
        
    tokenizer = SimpleTokenizer()
    
    # Consume generator stream
    print("--- Stream Start ---")
    for chunk in process_prompt_stream(prompt, config, tokenizer):
        print(chunk, end="", flush=True)

# Execution execution blockif __name__ == "__main__":
    # Passing an exact two-item tuple match matching requirements
    job_input: tuple[str, Literal["llama3", "gpt4"]] = ("Process high throughput requests natively", "llama3")
    run_pipeline_job(job_input, custom_temp=0.2)
